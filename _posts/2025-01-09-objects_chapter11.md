- 합성
  - 전체를 표현하는 객체가 부분을 표현하는 객체를 포함, 부분 객체의 코드를 재사용
  - 의존성은 런타임에 해결된다. <-> 컴파일 타임에 해결
  - has-a 관계 <-> is-a 관계
  - 동적인 관계. 실행 시점에 동적으로 변경 가능. <-> 정적인 관계. 변경 불가능.
  - 블랙박스 재사용 <-> 화이트박스 재사용. 구현이 노출됨.
  - 포함된 객체의 퍼블릭 인터페이스에 의존. 내부 구현이 변경되더라도 영향 최소화.
- 코드 재사용을 위해서는 객체 합성이 클래스 상속보다 더 좋은 방법이다[GOF94].

## 상속을 합성으로 변경하기
- 부모 클래스의 인스턴스를 자식 클래스의 인스턴스 변수로 선언하면 된다.
- 포워딩 메서드(forwarding method)[Bloch08]
  - 동일한 메서드를 호출하기 위해 추가된 메서드
  - 기존 클래스의 인터페이스를 그대로 외부에 제공하면서 구현에 대한 결합 없이 일부 작동 방식을 변경하고 싶은 경우 사용 가능한 유용한 기법
  - Set의 오퍼레이션을 오버라이딩한 인스턴스 메서드에서 내부의 HashSet 인스턴스에게 동일한 메서드 호출을 그대로 전달: 포워딩

## 상속으로 인한 조합의 폭발적인 증가
- 하나의 기능을 추가하거나 수정하기 위해 불필요하게 많은 수의 클래스를 추가하거나 수정해야 한다.
- 단일 상속만 지원하는 언어에서는 상속으로 인해 오히려 중복 코드의 양이 늘어날 수 있다.

### 추상 메서드와 훅 메서드
- 개방-폐쇄 원칙 만족하는 방법: 부모 클래스에 새로운 추상 메서드를 추가하고 부모 클래스의 다른 메서드 안에서 호출하는 것.
- 자식 클래스는 추상 메서드 오버라이딩해서 부모 클래스에서 정의한 플로우에 개입 가능해짐.
- 추상메서드 단점: 모든 자식 클래스가 오버라이딩해야. 대부분의 자식이 동일하게 구현하면 중복 코드 늘어남.
- 메서드에 기본 구현을 제공해서 해결
- 훅 메서드: 추상 메서드와 동일하게 자식에서 오버라이딩할 의도로 추가했지만 편의를 위해 기본 구현을 제공하는 메서드

### 클래스 폭발[Shalloway01] 문제 / 조합의 폭발 문제
- 상속의 남용으로 하나의 기능을 추가하기 위해 필요 이상으로 많은 수의 클래스를 추가해야 하는 경우
- 상속 관계는 변경 불가능하므로 자식과 부모의 다양한 조합이 필요한 상황에서 유일한 해결 방법은 조합의 수만큼 새로운 클래스를 추가하는 것
- 기능을 수정할 때도 문제

## 합성 관계로 변경하기
- 합성을 사용하면 구현 시점에 정책들의 관계를 고정시킬 필요가 없으며 실행 시점에 관계를 유연하게 변경 가능
- 조합을 구성하는 요소들을 개별 클래스로 구현한 후 실행 시점에 인스턴스를 조립
- 다양한 종류의 객체와 협력하기 위해 합성 관계를 사용하는 경우, 합성하는 객체의 타입을 인터페이스나 추상 클래스로 선언 -> 의존성 주입을 사용해 런타임에 필요한 객체(추상 클래스를 구현한 클래스의 인스턴스)를 설정할 수 있도록 구현

## 믹스인(보강 필요)
- 컴파일 시점에 필요한 코드 조각을 조합하는 재사용 방법 vs 합성: 실행 시점에 객체를 조합하는 재사용 방법
- 객체 생성 시 코드 일부를 클래스 안에 섞어 넣어 재사용하는 기법
- 클래스 사이 관계를 유연하게 재구성 가능 vs 상속
- 합성처럼 유연하면서도 상속처럼 쉽게 코드를 재사용 가능

### 쌓을 수 있는 변경[마틴 오더스키11]
- 특정 클래스에 대한 변경 또는 확장을 독립적으로 구현한 후 필요한 시점에 차례대로 추가할 수 있음
- 믹스인은 대상 클래스의 자식 클래스처럼 사용될 용도로 만들어지기 때문에 추상 서브클래스라고 부르기도 한다.[Brach90]
