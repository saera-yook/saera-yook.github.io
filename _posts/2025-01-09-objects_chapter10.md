## 상속과 중복 코드

### DRY(Don't Repeat Yourself) 원칙 / 단일 지점 제어(Single-Point Control) 원칙[Glass06b]
- 모든 지식은 시스템 내에서 단일하고, 애매하지 않고, 정말로 믿을 만한 표현 양식을 가져야 한다.[Hunt99]
- 중복 여부를 결정하는 기준은 코드가 변경에 반응하는 방식. 함께 수정해야 한다면 중복.

### 상속을 이용해서 중복 코드 제거하기
- 부모 클래스의 메서드 호출해 모든 통화요금 계산 후 10시 이후 통화요금을 차감
  - 개발자의 가정을 이해해야만 코드를 이해할 수 있다.
- 우리가 기대한 것은 10시 이전의 요금에서 10시 이후의 요금을 차감하는 것이 아니라 10시 이전의 요금과 10시 이후의 요금을 더하는 것
- 요구사항과 구현 사이의 차이가 크면 클수록 코드를 이해하기 어려워진다.

### 강하게 결합된 부모-자식
- 자식이 부모의 구현에 너무 강하게 결합되면 로직 추가를 위해 새로운 중복 코드를 만들어야 할 수도 -> 취약한 기반 클래스 문제
  - 코드 재사용을 목적으로 상속을 사용할 때 발생하는 가장 대표적인 문제
- 상속을 위한 경고
  1. 자식 클래스의 메서드 안에서 super 참조를 이용해 부모 클래스의 메서드를 직접 호출할 경우 두 클래스는 강하게 결합된다. super 호출을 제거할 수 있는 방법을 찾아 결합도를 제거하라.
  2. 상속받은 부모 클래스의 메서드가 자식 클래스의 내부 구조에 대한 규칙을 깨트릴 수 있다.
  3. 자식 클래스가 부모 클래스의 메서드를 오버라이딩할 경우 부모 클래스가 자신의 메서드를 사용하는 방법에 자식 클래스가 결합될 수 있다.
  4. 클래스를 상속하면 결합도로 인해 자식 클래스와 부모 클래스의 구현을 영원히 변경하지 않거나, 동시에 변경하거나 둘 중 하나를 선택할 수밖에 없다.

## 취약한 기반 클래스 문제[Holub04]
- 상속 문맥 안에서 결합도가 초래하는 문제점
- 상속 관계를 추가할수록 전체 시스템의 결합도는 높아진다. 캡슐화를 약화시킨다.
- 상속은 부모 클래스를 점진적으로 개선하는 것은 어렵게 만든다.
- 상속되기를 원한다면 상속을 위해 클래스를 설계하고 문서화해야. 그렇지 않은 경우 상속을 금지시켜야.[조슈아 블로치]
  - 내부 구현을 문서화해 공개하는 것 -> 캡슐화 위반. 트레이드오프

## 다시 살펴보기
### 추상화에 의존하자
- 부모와 자식 모두 추상화에 의존하도록 수정
- 코드 중복을 제거하기 위해 상속을 도입할 때 따르면 좋을 2가지 원칙
  - 두 메서드가 유사하게 보인다면 차이점을 메서드로 추출하라. 메서드 추출을 통해 두 메서드를 동일한 형태로 보이도록 만들 수 있다[Feathers04].
  - 부모 클래스의 코드를 하위로 내리지 말고 자식 클래스의 코드를 상위로 올려라. 부모의 구체 메서드를 자식으로 내리는 것보다 자식의 추상적인 메서드를 부모로 올리는 것이 재사용성과 응집도 측면에서 더 뛰어난 결과를 얻을 수 있다.[Metz12]

### 차이를 메서드로 추출하라
### 중복 코드를 부모 클래스로 올려라
- 부모 클래스를 추가하자. 부모는 추상 클래스로 구현하는 것이 적합.
- 공통 부분을 추상 부모 클래스로 이동. 메서드를 먼저. 컴파일 에러를 통해 꼭 필요한 인스턴스 변수와 메서드만 이동.
- 차이점을 캡슐화한 메서드는 시그니처만 동일하므로 시그니처만 이동. protected 추상 메서드로.
- '위로 올리기'전략은 실패했더라도 수정하기 쉽다.


- 상속으로 인한 결합은 피할 수 없다. 
  - 메서드 구현에 대한 결합은 추상 메서드를 추가함으로써 어느 정도 완화 가능
  - 인스턴스 변수에 대한 잠재적 결합을 제거할 수 있는 방법 없음.(부모에 인스턴스 변수 추가 시 자식 생성자도 모두 수정해야)

## 차이에 의한 프로그래밍[Feathers04]
- 기존 코드와 다른 부분만 추가함으로써 애플리케이션의 기능을 확장하는 방법
- 상속을 이용하면 재사용 쉬워 애플리케이션의 점진적인 정의가 가능해진다[Taivalsaari96].
- 상속의 오용과 남용은 애플리케이션을 이해하고 확장하기 어렵게 만든다.
- 정말로 필요한 경우에만 상속을 사용하라.
